## 一句话简介

这是一个以 Spring Boot 和 Spring Cloud 生态为基础的外卖业务微服务项目，通过网关统一接入请求，再由用户、购物车、订单和管理等服务分别承载业务能力；公共模块提供 JWT、异常、常量和 VO 等共享能力。

## 项目结构提纯

### 1. 微服务边界

| 模块              | 主要职责                     |
| --------------- | ------------------------ |
| `sky-gateway`   | 统一入口、请求路由、跨域处理和全局 JWT 认证 |
| `user-service`  | 用户登录、新增用户、地址簿等用户侧能力      |
| `cart-service`  | 购物车添加、查询、删除和清空           |
| `order-service` | 用户下单、历史订单、订单详情及部分订单操作    |
| `admin-service` | 后台人员管理、订单处理和报表统计         |
| `sky-common`    | JWT 工具、常量、异常及公共基础能力      |
| `sky-pojo`      | DTO、VO 等数据模型             |

整体请求路径可以概括为：

```text
客户端 -> sky-gateway -> 对应业务服务 -> 数据访问层
                         |
                         -> sky-common / sky-pojo
```

### 2. 网关认证流程

网关中的 `AuthGlobalFilter` 实现 Spring Cloud Gateway 的全局过滤器。请求进入后大致经过以下步骤：

1. 判断当前路径是否属于排除路径。
2. 如果不需要鉴权，直接放行。
3. 如果需要鉴权，从请求头读取用户 Token 或管理员 Token。
4. 根据 Token 类型选择相应配置并解析 JWT。
5. 解析成功后继续向下游服务转发；失败则返回认证错误。

资料指出项目在 `sky-gateway` 和 `sky-common` 中各有一个 `JwtTool`，两者都负责 JWT 解析。这说明认证逻辑在网关和公共模块之间存在复用或重复实现，需要结合源码进一步确认边界。

### 3. 核心业务流

#### 用户侧

- 用户登录后获得 JWT。
- 用户维护收货地址。
- 用户将商品加入购物车并管理购物车内容。
- 用户提交订单、查询历史订单和订单详情。
- 用户可以取消订单或执行“再来一单”等操作。

#### 管理侧

- 管理员处理订单，包括接单、拒单、取消、派送和完成。
- 管理端进行员工管理和报表统计。
- 报表相关能力通过订单数据和 VO 模型输出统计结果。

## 当前可复用的核心认知

1. 网关是认证和路由的统一入口，业务服务不直接承担外部流量入口职责。
2. 用户、购物车、订单、管理端按业务边界拆分，体现了按领域拆分微服务的思路。
